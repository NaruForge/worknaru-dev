# ADR 0011: 외부 사용자 데이터와 개발용 전체 초기화

- 날짜: 2026-09-14
- 상태: Superseded
- 후속 결정: [ADR 0012](0012-settings-data-management.md)가 Web에서 확인한 초기화의 재준비·새로고침만 자동으로 수행하도록 확장한다. 저장 위치·삭제 범위·데이터 보호와 CLI 초기화 절차는 유지한다.
- 관련 작업: [#29](https://github.com/NaruForge/worknaru-dev/issues/29)
- 승인 근거: 사용자가 개발 단계의 마이그레이션 금지·기존 데이터 삭제·전체 초기화와 수동 Web 새로고침을 선택하고 구현 계획 전체를 승인함.
- 이전 결정: [ADR 0004](0004-build-time-branding-and-data-root.md)의 저장 위치·기존 데이터 처리 결정을 대체한다. 빌드 시 브랜딩과 단일 저장 설정, 브랜드와 내부 ID의 독립성은 유지한다.

## Context

제품 checkout 내부의 사용자 데이터와 새 Agent의 암묵적 작업 폴더는 소스 수명과 사용자 작업을 연결한다. 개발 중 저장 구조를 자주 바꾸며 이전 Agent 이력을 유지할 필요가 없다. 마이그레이션·과거 이력 호환·백업 복구를 추가하면 검증할 상태만 늘어난다. 최초 실행을 반복해서 재현할 수 있어야 한다.

## Decision

기본 저장 루트는 Windows `%LOCALAPPDATA%\Worknaru-Dev`이며 명시적 `WORKNARU_DATA_DIR`가 우선한다. 제품 checkout과 데이터 루트의 동일·상하위 중첩을 실제 경로까지 검사한다. 관리 데이터·실행 checkout·Agent 작업 폴더는 영문·숫자·`-_.` 폴더명의 공백 없는 절대경로로 제한한다. 한글 표시 이름·대화 내용은 계속 지원한다.

전용 루트의 `worknaru-data.json`으로 제품·관리 파일 버전·저장 구조 버전·실제 경로·소유 checkout·초기화 상태를 식별한다. 새 루트는 없거나 비어 있어야 한다. 저장 구조가 다르면 중단한다. 개발 단계에서는 마이그레이션·이전 이력 호환·자동 이전·백업/롤백·다른 checkout에서 기존 데이터 재사용을 구현하지 않는다.

전체 초기화는 정지한 전용 루트만 대상으로 한다. 기본 명령은 미리보기이며 `--yes`로 실행한다. setup/start/reset은 공통 잠금을 사용한다. 삭제 전에 `resetting`을 기록하며 실패 시 실행을 막고 reset 재시도로 정리한다. 강제 종료의 잔류 잠금은 자동 삭제하지 않는다. legacy 전용 폴더는 삭제 대상으로만 검증하며 삭제 대상 밖의 빌드 잠금으로 재생성을 막는다.

전용 설정·인증·ID·Agent·대기열·DB/WAL/SHM·로그·설정 백업·managed 작업 파일·웹 staging과 임시 파일을 초기화한다. 외부 링크는 링크만 제거하며 managed Git worktree는 등록 관계가 확인될 때 Git으로 제거한다. 실제 작업 프로젝트·제품 소스·개인 Paseo 및 Provider 로그인 정보는 보존한다. 새 인스턴스의 setup/start는 명시적으로 실행한다.

Agent 작업 폴더는 호출자가 지정한다. 모델 조회부터 새 전송·dispatch·재개·권한 승인까지 서버에서 실제 폴더를 확인하며 오류는 전송 상태 변경 전에 처리한다. 해당 Agent의 자동 대기만 보류하며 기존 요청 ID 조회·조회/취소/보관·다른 Agent는 계속 사용할 수 있다. 정상 재시작의 지속성·중복 전송 방지·`uncertain` 계약은 유지한다.

열린 Web은 자동 전환하지 않는다. 기존 server ID 검사로 오래된 탭의 전송을 막으며 사용자가 새로고침하면 새 접속 ID를 읽는다. 테마·레이아웃은 ID별로 저장하고 새 인스턴스에서는 이전 선호와 Agent 선택·초안·캐시·미저장 편집을 복원하지 않는다. 정상 stop/start는 ID와 UI 선호를 유지한다.

실연동 검증은 저장소 밖의 실행별 데이터와 작업 fixture를 사용한다. 테스트 전용 `WORKNARU_TEST_ROOT`가 없으면 검증된 OS 임시 루트를 사용한다. 제품 설정의 개별 경로 옵션은 늘리지 않는다.

## Consequences

checkout을 제거해도 외부 사용자 데이터와 실제 작업 폴더는 독립적으로 남는다. 저장 구조 변경 뒤 데이터는 의도적으로 소실되며 개발자는 최초 상태를 반복 검증할 수 있다. 소유권·잠금·프로세스·링크·Git 등록이 불명확하면 삭제를 중단하므로 잔류 잠금이나 손상된 관리 기록은 수동 진단이 필요하다.

지원 경로를 좁혀 Windows 파일·도구 실행의 경계 조건을 줄인다. 사용자 홈이 미지원 경로라면 별도 외부 루트를 지정해야 하며 Provider 도구 전체의 경로 호환성을 보장하지는 않는다. 외부 Provider 자체 기록은 Worknaru 데이터와 별개의 수명이다. 제품 배포 단계에서 보존·업그레이드 정책이 필요해지면 별도 결정으로 다룬다.
