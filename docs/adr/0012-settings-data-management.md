# ADR 0012: 기존 실행기로 설정의 데이터 관리와 초기화 후 재시작 수행

- 날짜: 2026-09-15
- 상태: Accepted
- 관련 작업: [#38](https://github.com/NaruForge/worknaru-dev/issues/38)
- 승인 근거: 사용자가 설정의 저장 위치·폴더 열기·초기화 구현과 PR 작성을 지시했다. 별도 관리 연결 제안에 대해 시스템 확장을 피하고 기존 실행기가 Daemon 종료 → 초기화 → 재시작을 수행하도록 명시했다.
- 대체 범위: [ADR 0005](0005-local-development-cli-boundary.md)의 관리 명령 진입점을 CLI로 한정한 부분과 [ADR 0011](0011-external-data-and-development-reset.md)의 초기화 후 수동 준비·새로고침을 Web에서 확인한 요청에 한해 확장한다. 아래에 명시한 나머지 결정은 유지한다.
- 구현: [관리 실행기](../../apps/cli/dev-runner.mjs), [데이터 관리](../../apps/cli/data-management.mjs), [RPC 중계](../../apps/agent-service/server/data-management.mjs), [설정 UI](../../apps/web/src/shell/DataSettings.tsx).

## Context

저장 위치를 문서와 CLI로만 확인하면 실제 데이터가 어디에 있는지 화면에서 진단하기 어렵다. 전체 초기화는 파일을 쓰는 Daemon을 먼저 정지해야 한다. Daemon 내부에서 삭제를 계속하거나 종료 후 진행 보고만을 위한 별도 HTTP 서버·포트를 추가할 필요는 없다. 기존 관리 실행기는 Daemon 자식 핸들을 소유하고 Daemon 종료 후에도 살아 있다.

## Decision

Web의 개발 관리 클라이언트는 기존 Daemon WebSocket의 제한된 `development.data` RPC를 호출한다. 서버 플러그인은 데이터 루트·소유 checkout·실행기 기록·서버 ID를 확인하고 기존 Windows named pipe로 중계한다. CLI 실행기가 실제 저장 항목·폴더 열기·초기화를 소유한다. 제어 토큰과 파일 내용은 Web에 반환하지 않는다. 임의 경로나 실행 명령을 받지 않으며 폴더 열기는 조회한 항목의 경로를 다시 확인한다.

초기화 미리보기는 실행 환경과 연결한 60초짜리 일회성 확인값을 제공한다. 사용자가 삭제·중단·보존 범위와 재시작을 확인하면 실행기는 하나의 데이터 작업 잠금을 유지하며 다음을 수행한다.

1. 실제 소유한 Daemon을 정상 종료하고 PID·리스너·소유 기록 정리를 확인한다.
2. 기존 `resetData`의 정지·경로·worktree·링크 검사를 거쳐 전용 데이터 전체를 삭제한다.
3. 새 기본 설정·Agent 서비스와 기존 빌드 자산으로 같은 루트·주소의 Daemon을 시작한다. 기존 데이터는 복원하지 않는다.
4. Core·Agent 서비스·웹 자산 준비와 잠금 해제를 마친 후 공개 접속 정보에 완료 요청 ID와 새 서버 ID를 표시한다.

요청한 탭만 두 ID를 확인한 뒤 새로고침한다. 삭제 요청을 자동 재전송하지 않으며, 확인 시간 초과는 결과 미확인으로 표시한다. 실패한 삭제는 `resetting` 보호를 유지하고 새 Daemon을 시작하지 않는다. 다른 오래된 탭과 CLI 초기화는 기존 수동 새로고침 절차를 유지한다.

ADR 0005의 제품 앱 → Core → Runtime → Adapter 경계, Node 전용 개발 라이브러리 분리, Windows의 소유권 확인·숨겨진 실행기·고정 loopback 포트 6868·한 관리 환경·제한 시간과 실패 정리를 유지한다. 제품 Core/Runtime/Adapter에 파일·프로세스 관리 API를 넣지 않는다. 별도 관리 서버·포트·OS 서비스·일반적인 자동 재시작 정책을 도입하지 않는다.

ADR 0011의 저장소 밖 단일 데이터 루트·ASCII 절대경로·실제 경로와 checkout 소유권 검사, 저장 구조 버전·마이그레이션 금지, 외부 실제 프로젝트·개인 Paseo/Provider 로그인과 자체 기록 보존, 정상 재시작의 데이터 보존·Agent 폴더 명시·요청 중복 방지·검증 데이터 격리를 유지한다. CLI `dev reset --yes`는 삭제만 수행하며 setup/start를 자동 실행하지 않는다. 브랜딩 등 ADR 0004에서 이어받은 제한도 유지한다.

## Consequences

설정에서 실제 데이터 위치와 삭제 영향을 확인하고 초기화 후 빈 환경으로 돌아올 수 있다. 통신 중단 중의 세부 진행률은 제공하지 않으며 기존 주소에서 완료를 확인한다. 다른 기기에서 요청해도 탐색기는 Daemon PC에 열린다. 관리형 `dev start`와 Agent 서비스가 없는 실행 방식에서는 관리 기능을 사용할 수 없다.

검증은 경로·소유권·확인값·잠금·오류 테스트와 기존 실행기 회귀, 화면·키보드·접근성 검사, 외부 테스트 루트의 실제 초기화·재시작을 포함한다. 명령과 사용·복구 절차는 [Web 안내](../../apps/web/README.md#데이터-관리), 검증 결과는 연결한 Issue/PR에서 관리한다.
