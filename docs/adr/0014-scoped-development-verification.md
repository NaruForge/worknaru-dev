# ADR 0014: 변경 영향에 따른 검증과 실행 내 빌드 재사용

- 날짜: 2026-09-15
- 상태: Accepted
- 관련 작업: [#44](https://github.com/NaruForge/worknaru-dev/issues/44)
- 승인 근거: 사용자가 검증 비용 검토와 독립 리뷰를 거친 지침·스크립트·CI 개선안의 구현 및 병합을 승인했다.
- 대체 범위: [ADR 0013](0013-windows-ui-verification.md)의 모든 PR/push에 같은 UI CI를 실행하는 범위. Windows·Chromium·기준 이미지 검토·실패 처리 결정은 유지한다.
- 구현: [Agent 지침](../../AGENTS.md#개발과-검증), [UI 표준](../ui-design.md#실행과-검증), [검증 선택](../../apps/paseo-dev/README.md#검증-선택), [CI](../../.github/workflows/ui.yml).

## Context

모든 코드 작업의 로컬 전체 검증과 UI 전체 회귀 의무가 작은 변경에도 적용됐다. 실제 Agent·Web 검증은 명령 앞의 빌드와 setup/start의 빌드가 겹치며 소스가 같아도 여러 번 재빌드했다. 반면 전체 검증을 일괄 생략하면 자체 test 명령이 없는 공유 패키지와 CI에서 실행하지 않는 실연동 경계를 놓칠 수 있다.

## Decision

개발 중과 로컬 결과 전달에서는 변경 동작·영향받는 소비자의 실제 빌드·타입·테스트를 선택한다. 공통 계약·의존성·빌드와 저장·권한·실행 수명 변경은 범위를 확대한다. 코드 병합은 최종 변경에 대한 전체 자동 테스트와 UI 영향 시 전체 UI 회귀, 필요한 실연동 및 실제 필수 CI 조건을 충족한다. 같은 변경·환경·범위의 성공 근거를 재사용하되 CI 대기를 성공으로 간주하지 않는다.

선택 검증이 통과하고 구체적인 미해결 위험이 없으면 종료한다. 관련 코드·설정·환경 변화나 새로운 실패가 없는 반복 실행은 하지 않는다. 일반 문서 예외는 설명에 한정하며 lockfile·CI·fixture·기준 이미지는 검증 대상이다. 검사 명령 없음과 테스트 0건은 성공 근거가 아니다. 기록은 기존 Issue/PR을 사용한다.

전체 UI 명령의 동작·axe·화면 비교와 기준 이미지 정책을 유지한다. 별도 기능 전용 명령은 이미지 비교를 제외한다고 명시하며 전체 회귀의 대체 근거로 쓰지 않는다. Storybook 산출물 재사용은 같은 입력의 성공 빌드를 확인한 경우에만 명시적으로 선택한다. 디자인 논의의 대안 수는 의미 있는 선택에 맞추며 이미 승인된 방향의 시안·승인을 반복하지 않는다. 새 세션 3회의 AI 조립 평가는 그 평가가 업무인 경우에만 적용한다.

실연동 검증은 한 실행 안에서 최초 setup/start가 만든 빌드를 재사용한다. 소스·설정·의존성과 산출물을 확인하는 테스트 전용 경로를 사용하며 영구 캐시나 사용자용 빌드 생략 옵션은 추가하지 않는다. 일반 CLI setup/start의 빌드와 cold bootstrap·빌드 실패·소유권·잠금·정리 검사는 유지한다.

CI는 알려진 일반 Markdown 안내만 변경된 경우 diff 검사로 줄이고, 알 수 없는 경로·판정 불가·수동 실행에는 전체 검사를 적용한다. 삭제·이동의 원래 경로도 포함한다. 코드 PR의 tests/browser 전체 회귀는 유지하며 같은 PR의 오래된 실행만 취소한다. 코드별 CI 생략이나 복잡한 영향 분석은 도입하지 않는다.

## Consequences

작은 작업의 반복 전체 검증과 실연동의 중복 빌드가 줄어든다. 선택 범위가 잘못되면 누락이 생길 수 있으므로 소비자 테스트와 확대 조건을 담당 문서에 둔다. 검증 도구·기준 이미지 변경도 실제 검증 대상으로 취급한다. 성공 근거의 재사용에는 입력과 범위 확인이 필요하다.

실행 시간은 환경·Provider·준비 상태에 따라 다르므로 절감률을 미리 보장하지 않는다. 실제 명령의 시간·빌드 횟수·실패는 작업의 Issue/PR에 남긴다. 이 결정은 데이터 격리·소유권·권한·초기화 보존 정책이나 프로젝트 기록의 상태 체계를 변경하지 않는다.
