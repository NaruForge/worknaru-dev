# ADR 0010: 앱 탐색과 작업 세션의 분리

- 날짜: 2026-09-14
- 상태: Accepted
- 관련 작업: [#25](https://github.com/NaruForge/worknaru-dev/issues/25)
- 승인 근거: 사용자가 같은 데이터로 제공한 A/B/C 시안을 직접 검토해 B안을 선택하고 구현·PR 생성을 지시함.

## Context

Agent 목록과 대화만으로 구성한 초기 Web은 테마·전송 방식·연결 확인의 진입점이 분산되어 있었다. 다음 제품 기능을 추가할 때에도 사용자가 앱 전체 이동과 현재 작업의 탐색을 구별할 수 있어야 한다. 화면을 바꾸려고 Agent 훅을 다시 생성하면 초안·요청 ID·과거 대화의 읽던 위치를 잃을 수 있다.

동일 데이터·테마·화면 크기의 세 시안을 실행 가능한 페이지로 비교했다. [A는 상단 앱 탐색](../assets/shell-option-a.png), [B는 왼쪽 앱 탐색과 기능 목록 분리](../assets/shell-option-b.png), [C는 하나의 탐색 열 안에서 구역 구분](../assets/shell-option-c.png)을 사용한다. 사용자는 확장성을 논의한 뒤 B를 선택했다. 이미 승인한 디자인 시스템의 조립 원칙과 서버 경계는 [ADR 0009](0009-ui-design-system.md)를 유지한다.

## Decision

앱 전체 탐색, 기능별 목록, 중앙 작업, 선택적 상세 정보로 나눈다. 앱 탐색에는 현재 구현된 Agent와 설정만 둔다. 작은 화면에서는 앱 탐색을 위로 배치하고 목록·대화를 하나씩 표시한다. 통합 설정에 화면·Agent 동작·연결을 모으며 기존 바로가기는 같은 섹션을 연다.

Web의 `App`이 실행 환경별 세션을 소유한다. 탐색은 독립된 View/hash 모델로, Agent별 임시 상태는 `useAgentSession`으로 관리한다. 주소의 Agent·활성/보관함·목록/대화 구분과 설정 섹션은 브라우저 이력으로 다룬다. 기존 Agent hash는 호환 변환한다. 폴링은 사용자 탐색을 추가하지 않는다. hash만 사용하므로 정적 배포의 경로 fallback, 서버 라우팅, 라우터 패키지가 필요하지 않다.

Agent 초안·불명확한 전송의 요청 ID·권한 답변·확보한 이력과 읽던 위치는 같은 탭에서 Agent 또는 설정을 왕복할 때 유지한다. 비동기 결과는 시작한 Agent의 상태에만 적용한다. endpoint·target ID·예상 server ID를 세션 경계로 삼아 다른 실행 환경과 섞이지 않게 한다. 새로고침 이후의 대화 초안 저장이나 기기 동기화는 제공하지 않는다. 서버가 기록과 실행의 원본이다.

테마·패널 너비·접힘은 브라우저 선호로 저장한다. 공통 UI의 `PanelGroup`과 `ResizablePanel`이 토큰 기반 제한, 공간 측정, 포인터와 키보드 조절을 맡는다. Web은 저장과 명시적인 접기/펼치기·초점 복귀를 맡는다. 공통 패널 내부의 검증된 숫자형 CSS 변수만 동적 크기 계약으로 허용하며 앱의 스타일 검사를 완화하지 않는다.

전송 방식은 기존 Core의 revision 기반 저장을 사용한다. 미저장 편집은 같은 탭에 남기고 사용자가 저장·취소한다. 자동 저장하거나 이동을 이유로 버리지 않는다. 새로고침·탭 종료에는 브라우저 경고를 요청한다. 새로운 공유 설정 엔진, 전역 상태 라이브러리, Paseo 서버·프로토콜 변경은 도입하지 않는다.

## Consequences

사용자는 현재 작업을 유지하면서 설정을 확인할 수 있고, 향후 기능은 앱 탐색과 자체 목록을 같은 구조로 조립할 수 있다. B안의 별도 탐색 영역은 데스크톱 가로 공간을 소비하므로 목록·상세 패널 조절과 작은 화면 전환이 필요하다. A보다 앱 탐색이 세로 공간을 아끼지만 가로 공간을 더 사용한다. C보다 영역 구분은 명확하지만 탐색 열이 늘어난다.

화면 수명과 세션 수명을 분리하면서 늦은 응답, 이력 공백, 스크롤 복원에 대한 관리와 테스트 비용이 생긴다. 방문한 Agent의 이력은 탭 수명 동안 메모리에 남는다. 대규모 사용에서 캐시 제거가 필요해지면 초안·요청 ID·읽던 위치를 보존하는 별도 정책을 검토한다. 현재는 기능 확장을 위한 범용 탭·도킹·Module 화면을 미리 구현하지 않는다.

브라우저 선호 저장은 사용할 수 없거나 손상될 수 있으므로 검증·기본값·초기화를 제공한다. hash 주소는 서버의 의미 있는 경로를 제공하지 않지만 현재 단일 정적 앱 배포와 호환된다. 구현·선택 화면·검증 증거는 관련 작업의 PR에서 확인한다.
